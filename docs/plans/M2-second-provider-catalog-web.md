# M2 — Second provider, model catalogue, web tools

## Goal

`bingo --print --provider openai "…"` runs the same coding turn over the OpenAI Responses API that M1 runs over Anthropic, which is what proves the `Provider` trait. A model's window and output budget come from one catalogue (models.dev) that the user can override and the server can correct, so the kernel measures every model with the right ruler. `WebFetch` and `WebSearch` join the toolset.

## Bricks, in build order (owner)

1. **ADR-0004 + sdk** (kernel) — split the model facts by owner: `Provider::endpoint(model) -> EndpointCapabilities{images, count_tokens, caching}` is what the wire knows; `ModelCapabilities` stays as the *resolved* facts a turn reads; `ModelInfo` loses `capabilities` (the catalogue answers). One sdk change, touching `provider-fake`, `provider-anthropic` (its model table is deleted, as its own comment promised) and the new `provider-openai`.
2. **`bingo-core::models`** (kernel) — `catalog`: a models.dev snapshot (`crates/bingo-core/models.dev.json`, regenerated by `scripts/models_dev.sh`; raw api.json shape pruned to `limit`, `reasoning`, `modalities.input`) read once, looked up as `(provider, model)` → longest-prefix in that provider (dated snapshots) → any provider with that id; `declared`: the fifth kernel settings key `models` (`"<provider>/<model>": {contextWindow, maxOutput, reasoning, images}`, each field optional); `learned`: `window_from_overflow(message)` ported from `src/api/learned.rs:101-140` and an in-memory `(provider, model) → window` clamp recorded by the turn on `ContextOverflow` and applied at the next session open; `resolve`: the pure function `declared > learned clamp > catalogue > default(200k, 8k, no reasoning, images)` with the endpoint facts composed in (`images = model && endpoint`); `max_tokens = min(declared maxTokens | min(max_output, 32k), window / 2)` so the effective window is never below half; `vision`: `project_images_out(messages, note)` applied in `assemble()` when the resolved model has no vision — the note `[image omitted: <model> has no vision]` replaces the part on the wire only.
3. **`bingo-provider-openai`** (worker A) — Responses API: `POST /v1/responses` streaming; `Variant::{Default, Codex}` in one enum with request-body isolation (Codex: `/codex/responses`, `store:false`, no `max_output_tokens`, `include:["reasoning.encrypted_content"]`, `originator`/`ChatGPT-Account-Id` headers — encoded and tested now, registered in M10 when OAuth exists); system → one `instructions` string; messages → `input` items (`input_text`/`input_image` data URLs, assistant `output_text`, `function_call`/`function_call_output`, `reasoning` items replayed from `provider_metadata["openai"]` with `encrypted_content`); tools → `{"type":"function", strict:false}`; `reasoning.effort` clamped per family to what the model accepts (the models.dev `reasoning_options` are the oracle); SSE → `ModelEvent` (`response.created` metadata, `output_item.added/done` start/end per item type, `output_text.delta`, both `reasoning_summary_text.delta` and `reasoning_text.delta`, `function_call_arguments.delta/done` → `ToolInputDelta`/`ToolCall`, `response.completed/incomplete` → `Finish` with usage `input_tokens_details.cached_tokens` and `output_tokens_details.reasoning_tokens`, `incomplete_details.reason=max_output_tokens` → Length, `response.failed`/`error` → `Err`); errors (401/403 Auth, 429 RateLimited with `retry-after` in seconds or `retry_after_ms` in the body, 400 `context_length_exceeded`/"maximum context length" → ContextOverflow, 5xx Server, 60 s idle → Timeout); `GET /v1/models` tolerant of `data[]`, `models[]` and a string array; key from `OPENAI_API_KEY` or `openai.apiKey`, `OPENAI_BASE_URL`/`openai.baseUrl`; `auth()` hint names both; endpoint facts `images: true` (`openai.images: false` for a proxy that strips them), `count_tokens: false`, `caching: true`.
4. **`bingo-tool-web`** (worker B) — `WebFetch{url, prompt?}`: `url` crate validation (≤2000 chars, no credentials, a host with a dot), http→https upgrade, ≤10 redirects, 60 s, 10 MB streamed cap, readability (`dom_smoothie`) → markdown (`htmd`), 100 000-char result, 15-minute / 50 MB in-process cache; subjects `Url` on the canonical URL; the pre-approved documentation hosts of the old `src/preapproved.rs` are the tool's `read_only` claim for that call, so they pass the default gate and every other host asks. `WebSearch{query, allowed_domains?, blocked_domains?}`: one `SearchBackend` trait with two implementations, DuckDuckGo HTML (keyless default, ported from `src/tool/websearch.rs:123-166`) and Brave (`web.braveApiKey` / `BRAVE_API_KEY`); ≤8 hits `title / url / snippet`; 20 s. Config claim `web` (`braveApiKey`, `search: "duckduckgo" | "brave"`).
5. **`bingo`** (kernel) — register `OpenAiPlugin` and `WebPlugin`; `tests/cli.rs` gains `--provider openai` against a wiremock Responses endpoint reached through `OPENAI_BASE_URL`, and a `WebFetch` of a wiremock page.

## Non-goals

Refreshing the catalogue from models.dev at runtime (the snapshot is the raw api.json shape so a refresh is a download into `<data_dir>/models.dev.json` and nothing else; it lands with the command dispatcher in M3). Persisting learned windows (with the store, M3). Applying a learned window to the session that learned it (the overflow ladder, M4). OAuth and the `codex` provider registration (M10). Tavily/Exa backends. Cost accounting from the catalogue. Extracting path arguments from Bash commands for the sensitive-path check (needs Bash to classify destructive verbs; carried).

## Risks touched

R1 sdk churn — this is the one change M2 allows, made first so both workers build on it. R4 provider quirks — every quirk lands with a fixture; the two delta names and the Codex isolation are regression tests, not comments. Catalogue disagreement with vendor docs (models.dev lists 1M windows for Claude 4.5+) — the learned clamp corrects the first overflow, `models` in settings corrects it before that.

- Catalogue: exact, dated-snapshot prefix, cross-provider id, unknown → default; four proptests on `resolve`/`max_tokens`; the three overflow shapes; the embedded snapshot must parse (a test) and knows both first-party providers.
- Vision: a blind scripted model receives `[image omitted: m has no vision]` in place of the part; the items keep the image.
- Web: validation table, https upgrade (loopback exempt), streamed cap with nothing kept, cache hit with `expect(1)`, readability on a fixture, `read_only` for `docs.rs`/`github.com/anthropics/x` and not `example.com`/`github.com/other`, DuckDuckGo and Brave parsers on fixtures, allowed/blocked filtering.

- sdk changed once (`c50e8ca`), ADR-0004 names the plugins.

Decisions taken while integrating (each is a commit body too):

- `TurnConfig.model: ModelChoice{provider, id, capabilities, max_tokens, reasoning, learned}` — the host's resolution is one noun, and the 16-field cohesion cap said so.
- The ruler counts cached input: `Usage::input_total()`; the three counts stay apart on the wire (Anthropic reports them apart; OpenAI's `cached_tokens` is split out).
- A reasoning part with replay data and no text is folded back into the request (`3773b79`); the accumulator kept it, the fold dropped it.
- OpenAI sends `store:false` + `include:["reasoning.encrypted_content"]` on both variants; `effort_for` never answers `none` (an `Option` already says that); a failed tool result is `{"is_error":true,"content":…}` because the wire has no flag.
- `WebFetch` is `ResultLimit::SelfBounded` at 100 000 chars (the kernel's 50 000 would make the cap dead code); `http`→`https` skips loopback so a local server stays reachable; `docs.rs` joins the pre-approved list; a DuckDuckGo challenge page is an error, not "no results".
