# 0007 — The wire: JSON-RPC 2.0 over NDJSON, methods 1:1 with `HostApi`, events verbatim

## Context

A GUI, an IDE, an IM gateway and a remote TUI all need to drive the kernel from another process. The old project's app-server had 23 methods and 39 notification types mirroring internal enums, and no consumer; every mirror drifted. ADR-0002 made `bingo_sdk::Event` the one event type and every surface a client of it; the wire has to be that contract with an envelope and nothing else. ACP is JSON-RPC, Codex's app-server is JSON-RPC, OpenClaw's `req/res/event` is a renaming of it.

## Decision

1. **Transport.** JSON-RPC 2.0, one message per line, UTF-8, over the server's stdin/stdout (`bingo serve --stdio`). Stdout carries nothing but JSON-RPC messages; diagnostics go to stderr. A WebSocket transport carries the same bytes and arrives with the first client that needs one.
2. **Methods are `HostApi` and `SessionPort`, one each, plus a handshake:** `initialize {client, protocol}` → `{protocol, name, version, capabilities}` and must come first (anything else is `NOT_INITIALIZED`); `shutdown`; `session/list {filter}`; `session/open {selector}` → `{session, snapshot}`; `session/close {session}` (detach); `session/delete {session}`; `session/history {session, page}` → `HistoryChunk`; `session/events {session, since}` (resync: frames after `since` are re-sent); `session/submit {session, intent, input}`; `session/interrupt {session, intent, scope}`; `session/answer {session, intent, interaction, answer, activation}`; `catalog/read {kind}` → `Catalog`; `gateway/subscribe`. Thirteen. Every params and result type is an sdk type or a struct of sdk types.
3. **Events are notifications, verbatim.** `event` carries a `Frame` exactly as the sdk serialises it; `gateway/event` carries a `GatewayEvent`. A client folds frames with `SessionState::apply`, the same reducer the kernel runs. The `session/open` response (snapshot at seq N) is written before any `event` of that session with seq > N; frames of one session arrive in seq order; `Lagged{from, to}` means "call `session/events {since: <your seq>}`".
4. **Writes return nothing.** `submit`, `interrupt` and `answer` answer `{}` as soon as the mailbox took them; the outcome is the `IntentAck` event whose `intent` is the client-minted ULID, which is also the idempotency key.
5. **Errors.** JSON-RPC `error.code`: -32700 parse, -32600 invalid request, -32601 unknown method, -32602 invalid params, -32000 for every `KernelError`, whose stable `ErrorCode` string travels in `error.data.code` and whose text is `error.message`.
6. **The schema is committed.** `schema/rpc.json`: JSON Schema `$defs` for every wire type generated by schemars from the sdk, plus a `methods` table (`params` and `result` refs) and a `notifications` table. A test regenerates it and fails on any difference, naming the command that updates it; another asserts every property name is camelCase.
7. **`RemoteKernel`** implements `HostApi` and `SessionPort` over the wire, so a surface written against `HostHandle` runs remote by changing one constructor. It is also the black-box harness.
8. **`--print --output-format stream-json` is a lossy compatibility encoder** in the print surface: Claude Code's envelope (`system/init`, `assistant`, `user` with `tool_result`, `result` with usage) so a host that speaks that dialect drives bingo without a plugin. It is a projection of frames, never a second event model; the kernel does not know it exists.

## Consequences

- The wire is the sdk, and building it found two things the sdk had wrong: variant fields of its tagged enums reached the wire in snake_case while struct fields were camelCase (fixed with `rename_all_fields`; the journal keeps version 1 — no journal had left a developer's machine), and `HostApi::catalog` was synchronous, which a remote implementation cannot honour (now `async` and fallible). Touched: `bingo-core`, `bingo-surface-print`, `bingo-surface-rpc`. A surface crate may not declare an enum whose name ends in `Event` (`scripts/check_discipline.sh`).
- A host can reconstruct any client view from the snapshot and the frames; `session/history` exists only for paging a long transcript.
- One stdio server serves one client; two processes on one session are refused by the store's lock (ADR-0005). Concurrent clients of one server come with the WebSocket transport.
- `bingo serve` is the first surface with no prompt and no session of its own; `SurfaceOptions.selector` is ignored by it.
