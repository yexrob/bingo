bingo 重写架构

一个最小内核 —— 会话 actor、有序事件日志（事件中心）、turn 状态机、权限门、插件宿主 —— 其余一切是经稳定 trait 注册的插件；每个界面（TUI、print、GUI、ACP、IM）都只是事件的订阅者和唯一提交入口的调用者。

01内核与插件的边界

内核是「把所有功能拆掉之后，仍然能用脚本化 provider 跑完一轮、并发出一条无缝事件流」的那部分。判断标准只有一条：一个插件不能定义插件被咨询的顺序，能定义顺序的东西才进内核。

在内核（bingo-core / bingo-sdk）为什么不能是插件
领域词汇：ids、Message/ContentPart、Item、Event、Interaction、SessionState两个插件要能对话，名词必须不属于任何一方。放在 sdk，core 只是消费者之一。
会话 actor：id 铸造、seq、turn/交互/队列注册表、快照顺序是全局性质。谁分配 seq、谁裁决两个竞争写谁赢，谁就是内核。
turn 状态机 + 工具执行器它是「插件被调用的顺序」本身，且不含任何功能名词——收件箱、任务提醒、团队规范都是它调用的 contributor。
权限门（不是策略）「用户说不」在此唯一执行。策略（模式、规则表、敏感目录）是插件；没有策略时门拒绝一切非只读。
插件宿主：manifest、拓扑序、service、配置分层、HostApi插件注册进去的那个东西，也拥有唯一提交入口与唯一订阅入口。

其余全是插件，包括 Bash/Read/Edit、每个 provider、每个界面、转录存储、压缩策略、记忆、skills、MCP、子代理、团队、房间、任务、经验库。

02分层总览

自上而下：客户端 → 唯一入口/出口 → 内核 → 插件贡献 → 外部世界。橙色是内核；灰色是插件；虚线框是进程外的东西。

03事件中心

不是一条全局无类型总线（那会重新引入「谁先谁后」问题），而是每个会话一条有序日志 + 每个订阅者一条有界通道。所有生产者（turn loop、工具、插件）都经 actor 发布；所有消费者都经 subscribe 读取。

I1内核永不阻塞在客户端上——每订阅者有界通道，溢出发 Lagged{from,to}，客户端回读日志。 I3写操作不返回回执——submit/interrupt/answer 带客户端铸造的 IntentId，返回 ()。 I4每个动作恰有一个处理者，且在内核——界面在 Cargo 依赖上触达不到 core。 I6日志即真相，模型上下文是派生——压缩与回退是事件，永不改写历史。 I7交互是资源不是调用——由事件打开、在快照可见、任一附着者按 id 只答一次、带 by 解决。

04一轮对话的时序

TUI 提交「跑测试」；模型决定编辑文件；权限提示同时到达 TUI 与 GUI；GUI 先点了允许；TUI 迟到的回答被拒绝；工具执行完成；轮结束。所有人看到的都是同一条帧序列。

05Turn 状态机

内核里唯一的「流程」。它只知道 provider、tool、policy、hook、contributor 这些 trait，不知道收件箱、雇员、任务提醒——那些在旧项目里都长在 575 行的 query_loop 内部，现在是插件注册的 contributor。

06会话 = 一条日志

一个会话就是一份持久上下文、一条日志、一个 actor——没有「主会话里装着多个对话」。子代理是带 parent 链接的子会话；房间是一个没有模型的会话。日志之上跑两个纯 reducer：一个给客户端，一个给模型。

07Crate 与依赖方向

把设计里已经存在的接缝变成 Cargo 边界。旧项目是一个 148K 行的单 crate，工具层反向依赖 TUI，任何改动全量重链；这里的每条禁止边都由 CI 用 cargo metadata 断言。

08稳定 trait 一览

全部 object-safe，以 Arc<dyn T> 持有；失败关闭的默认值；扩展靠 #[non_exhaustive]、默认方法和 meta。

09路线图

每个里程碑都能从终端用、都以验证收尾、plan 文件先于代码。RPC 在 TUI 之前——「GUI-ready」只有在 TUI 之前就存在一个非 TUI 客户端时才是真的；子代理与协作是 first-class，紧跟 hooks/MCP。

10生态接入

被别人驱动

  • bingo serve --stdio：OpenClaw registerCliBackend、Hermes、CI 脚本；--print --output-format stream-json 就是它的预设。
  • bingo-acp：一份有损投影，同时接入 Zed/IDE、Hermes、OpenClaw acpx——三个宿主换一个适配器。
  • WebSocket + 发布的 schema：OpenClaw 若想写原生 AgentHarness，其 req/res/event 与 JSON-RPC 只是信封改名。

自己托管 IM

  • bingo-channels：会话键 feishu/oc_abc/om_thread，首段 = 铸造插件 id，内核强制唯一。
  • Deliverer 纯 reducer：帧 → 编辑 / 分块 / typing / 审批按钮；与 TUI 用同一套帧 fixture 测。
  • 群聊里每条用户 item 记 origin.principal；GUI/TUI/ACP 看到同样的「谁说的」。
待决（各在对应里程碑的 ADR 里定）：async_trait 与 AFIT；房间作为「无模型会话」的内核扩展（M9 前）；子会话在存储里按父目录还是平铺（M3 前）；ACP v1 的 session/prompt 保持打开与队列优先的映射。开源库选型另有一份调研报告。
