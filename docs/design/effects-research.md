# Terminal visual effects — survey, and what bingo should take

Research 2026-09-04. Every star count / license / release date below was read today from the GitHub REST API or the crates.io API against the URL in the row. Read against `docs/design/tui.md` §6 and `crates/bingo-surface-tui/src/{motion.rs,clock.rs,theme.rs}`.

## 1. What bingo already has (the baseline the survey is judged against)

`crates/bingo-surface-tui/src/clock.rs` already ships a tween kit: `Anim{started,len}` with `progress()` and `step(n)`, `ease_out` (cubic), `ease_in_out`, `cycle`, `phase`, `breath`, `alternating`, and `moves()` for `BINGO_MOTION=off`. `theme.rs` ships the colour half: `mix`, `scaled`, `steps`, and the named ramps `breath` / `pulse` / `comet` / `attention` / `fading` / `warming` — each with a **three-way degrade** (`Colors::True` interpolates, `Colors::Ansi` collapses to the two ends at the halfway mark, `Colors::Plain` returns an empty `Style`). `run.rs` runs a demand-driven 30 fps tick gated on `animating()` and draws nothing at all when idle.

That is, structurally, what tachyonfx is: a phase → style function applied to a ratatui `Buffer`. **bingo has already hand-rolled the engine.** The only thing a library would add is a catalogue of named effects.

Not built, though the design already sanctions it: the progress **gradient fill** (§4 says `presence` → glow; `views/progress.rs:27` paints flat `presence`) and the **unbounded sheen** (`views/progress.rs:4` — "the sheen that walks it is M11c's", never landed; `SHEEN` is a static 3-cell run). Not used anywhere: **synchronized output** (`grep -rn Synchronized crates/` is empty).

## 3. What bingo should take

### The finding that shapes everything else

§6's motion table is nearly saturated already — breath, glow, comet tail, bullet pulse, completion flash, card reveal, sheet slide, notice fade, needs-you pulse, eased scroll, session crossfade, context warming. **"Young and energetic" is not more animation.** Past a certain density more motion reads as *nervous*, not young, and §1's own line is "alive is not busy". Energy in a terminal comes from three things the survey confirms and bingo currently under-spends: (a) motion that lands on the **gestures a person makes**, not only on what the machine does — bingo animates the model constantly and the *person* not at all; (b) **rhythm that varies** with state, so the pulse is information and not a metronome; (c) **smoothness** — a torn frame at 30 fps kills more perceived quality than any effect adds. Hence the priority order below, in which the first item is not an effect.

### The recommended set

**0. Synchronized output (`CSI ? 2026 h/l`) around every draw.** *Where:* `run.rs`'s draw, once. *What:* the terminal composites the frame atomically instead of mid-write. *Cost:* two escape sequences per frame; no CPU, no new dependency — `crossterm` 0.29 already exports `terminal::BeginSynchronizedUpdate` / `EndSynchronizedUpdate` and bingo already depends on crossterm 0.29. *Library:* none needed. *Degrades:* a terminal that does not know mode 2026 ignores it silently; unaffected by `BINGO_MOTION=off` and `NO_COLOR`. Do this first: every effect below reads better through it, and the 5 000-block scroll in §9 is exactly the case it fixes.

**1. Send ignition.** *What:* on `⏎`, the input box's border runs one bright sweep left-to-right in `presence`→glow over ~200 ms (6 frames), and the new `>` bar's `raised` ground fades in over 3 frames. *Where:* the single most repeated gesture in the whole surface, and today it has **no** feedback at all — the row simply exists. *Cost:* 6 frames on a keypress, on a loop that is about to animate anyway. *Library:* hand-rolled; it is `Anim::new(len=200ms)` + `theme::mix` + a per-column phase — under 20 lines. tachyonfx's `sweep_in` with a `SweepPattern` is the same thing with a dependency attached. *Degrades:* `BINGO_MOTION=off` → the bar appears at rest, no sweep; `NO_COLOR` → nothing at all (the ramp is pure colour, and §4 forbids colour carrying a fact alone, so nothing is lost). **The highest-value single addition.**

**2. Tool-done sweep, replacing the 33 ms bold flash.** *What:* when `⏺` turns `good`, run `good` left-to-right across the row's name over ~200 ms and settle. *Where:* the moment a tool finishes — the beat a person is actually waiting on. *Cost:* 6 frames per completion. *Library:* hand-rolled over the `Line`'s spans, same brick as #1. *Degrades:* motion off → today's behaviour exactly (straight to `good`); `NO_COLOR` → the bold frame alone. A 33 ms flash is below the threshold at which a person registers it as *something happening*; 200 ms is where "it landed" lives.

**3. The breath's period tracks the work.** *What:* the sparkle and the input glow breathe faster while output tokens are arriving and slower while a tool is blocking. *Where:* the activity row, continuously. *Cost:* **zero** — `clock::breath(now, period)` already takes a period; only the argument changes. *Library:* hand-rolled, one expression. *Degrades:* unchanged (motion off already freezes it). This is the cheapest energy in the list and the most defensible: §6's first principle is "every motion reports a state change", and a fixed 1.6 s breath reports nothing beyond "a turn is running", which the row's presence already says.

**4. The permission card's border breathes while unanswered.** *What:* the card's `presence` border takes `theme::attention`'s 1 Hz beat until it is answered. *Where:* the permission ask — first glance, §2. *Cost:* 1 Hz on an already-open card. *Library:* hand-rolled; `attention()` exists and is already used for the `needs you` notice, the child row and the switcher line. *Degrades:* motion off → rests on `presence` (`attention` already does this); `NO_COLOR` → the border is still the only box on screen. This makes "wants you" one cue said in four places instead of three plus an exception.

**5. The progress gradient and the sheen — finish what §4/§5 already promise.** *What:* the bounded fill ramps `presence` → glow across its lit run (§4: "Gradients exist in two places only"); the unbounded bar walks its 3-cell `SHEEN` along the track. *Where:* rail cards and plugin `View::Progress`. *Cost:* the sheen is a phase → offset, ~4 fps is enough. *Library:* hand-rolled; `views/progress.rs:4` has been carrying the TODO since M11c. *Degrades:* motion off → the sheen parks at the head, the gradient stays (it is not motion); `NO_COLOR` → `theme::mix` returns plain, the `█`/`░` shapes carry it. Free taste: no new decision is needed, only the code.

**6. An error flares and cools.** *What:* on a failed tool or turn, the row's text starts at `bad` and ramps to `text` over ~400 ms — a flare that settles, not a shake. *Where:* the one moment §6 currently has no cue for at all. *Cost:* 12 frames, rare. *Library:* hand-rolled; `theme::fading` is already this function with the ends swapped. *Degrades:* motion off → `bad` bullet, plain text, as today; `NO_COLOR` → the glyph. Explicitly **not** a shake or a jitter: §3's "nothing jumps" outranks it, and the 2026-09-02 withdrawal of the rise is the precedent.

**7. Session switch: a top-down wipe instead of the 2-frame crossfade.** *What:* stepping into a child reveals its transcript top-down over 3 frames, the way a card does. *Where:* `⏎` on a child row, `ctrl+g`. *Cost:* 3 frames per switch. *Library:* hand-rolled; the card reveal's own brick. *Degrades:* motion off → whole on the first frame, as layers already do. Lowest priority — a dim crossfade reads as a flicker, a wipe reads as a move, but the current cue is not *wrong*.

**Rationale.** Six of the seven are style ramps over rows that already exist, written with `Anim` + `theme::mix`, and cost between zero and 6 frames on beats that are already redrawing. Nothing new appears on screen, so §3's one-line-of-furniture rule and "nothing jumps" are untouched, and every one of them reports a state change §6 would sign off on. The energy comes from **#1 and #3** — giving the person's own gesture a beat, and making the machine's pulse tell the truth about what it is doing. That is what reads as young: responsiveness, not decoration.

### The dependency question: tachyonfx

**Recommendation: do not take it.** It is the right library and it is not the wrong call for someone else — MIT, 1,293 ★, active (0.25.1 on 2026-07-05), now under the ratatui org, and its ratatui-core 0.1.2 pin matches bingo's ratatui 0.30. But: `cargo tree --workspace -e normal` is at **331 crates against a `max_dependencies` of 331** — the budget is exactly full, so tachyonfx is +5 (`tachyonfx`, `bon`, `bon-macros`, `prettyplease`, `micromath`) **and** a budget raise **and** an ADR line. What it buys is a catalogue: of its ~40 effects, the ones matching the seven above are `sweep_in`, `fade_from`, `translate` and the timing combinators — and bingo has already written the engine those sit on (`Anim`, `ease_out`, `ease_in_out`, `phase`, `mix`, `scaled`, `steps`), with the one thing tachyonfx does *not* have: a tested three-way degrade to `Colors::Ansi` and `Colors::Plain`, which is what `NO_COLOR` in §7 requires. Taking it would mean either bypassing that degrade or wrapping every `fx::` call in it — the second representation the project forbids. **Reconsider only if** the design ever wants full-buffer transitions (a real dissolve between sessions, a shader over the whole frame); nothing in §6 does.

**ttfx is not a candidate at all**, whatever its charm: it is a CLI for one-shot animation of *static* piped text, unpublished on crates.io (git dependency only), and its 37 effects are full-screen takeovers. On a live transcript they would re-animate on every reflow and destroy selection, search and the `--print` degrade. It is worth reading for its `src/effects/` implementations — 37 worked examples of terminal effect maths in Rust, MIT — and worth using in `scripts/` for a demo GIF. Not in the binary.

### Refuse, explicitly

1. **Full-screen text effects on arriving model text** (ttfx/TTE's matrix, burn, decrypt, fireworks, blackhole; chalk-animation's glitch). The transcript is a virtualised, scrollable, searchable, selectable, copyable record that `--print` must be able to reproduce (§5's degrade column, and `motion.rs`'s `the_tail_is_style_and_never_text`). An effect that rewrites *characters* rather than styles breaks all five. The comet tail is the right shape of this idea and it is already built.
2. **A typewriter / character-by-character reveal.** The model already streams at its own rate; a typewriter would be a *second representation* of arrival speed that lies about the first, and it slows reading of the thing a person is there to read. Refused by "one fact, one representation".
3. **Rainbows and hue cycling** (chalk-animation `rainbow`/`neon`, gradient-string's 13 presets, tachyonfx `hsl_shift`). §4 spends exactly one warm colour and one cool colour, each with a job, and says colour never carries a fact alone. A rainbow carries no fact; it is the clearest generative cliché in this space.
4. **Particles, sparkles, confetti on success** (`confettysh`, `confetty`, harmonica's projectiles). Novelty that reads as young in minute one reads as noise in hour two, and a person watching a build fail does not want confetti. §1: "nothing moves for decoration".
5. **A spinner zoo.** cli-spinners has 90 and bubbles has 12; bingo has one presence mark with four glyphs and eight verbs. A second spinner shape would be a second way to say "working" — and the four-glyph `✻ ✢ ✶ ✽` *is* bingo's signature.
6. **Anything that moves a row.** Bounce, slide-in blocks, spring overshoot on scroll, the withdrawn rise. Already decided on 2026-09-02 and dearly paid for: the transcript hangs from the foot, so a block that takes two extra rows makes the whole screen jump. Springs (harmonica, bubbles' progress) are attractive and their overshoot is exactly the property this surface cannot afford.

### The restrained alternative

**Set B: #0, #3, #4, #5.** Synchronized output; the breath's period tracks the work; the card's border breathes; the progress gradient and sheen land. Nothing new appears on screen and no new motion is invented — three existing surfaces gain one more truthful state each, one documented-but-unbuilt cue is finished, and tearing goes away. *Rationale:* if the read is that §6 is already at the right density, then the honest move is to make what is there smoother and more truthful rather than to add. It is also the set with no taste risk: every line of it is already sanctioned by the design doc, so it needs no new decision entry in §10. Set B costs roughly a day; the full set costs a few, and the difference between them is #1 and #2 — the two that put motion on the *person's* side of the conversation, which is the actual answer to "make it feel young".
