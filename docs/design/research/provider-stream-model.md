# Vercel `@ai-sdk/provider` vs litellm as references for a Rust coding-agent kernel

**Headline correction to the brief:** the spec is now **V4**, not V3. Timeline from npm ([provider](https://registry.npmjs.org/@ai-sdk/provider), [ai](https://registry.npmjs.org/ai)): V2 → `ai@5` (2025-07-31), V3 → `ai@6` (2025-12-22), **V4 → `ai@7` (2026-06-25)**. Current: `@ai-sdk/provider@4.0.8` (2026-08-25), `ai@7.0.83`, `provider-utils@5.0.32`, Apache-2.0. The repo keeps only `v2/`, `v3/`, `v4/` dirs ([tree](https://github.com/vercel/ai/tree/main/packages/provider/src/language-model)); V1 is gone. Everything below is verified from V3/V4 source unless flagged.

## A. Vercel provider spec

**A2. `LanguageModelV4`** ([src](https://raw.githubusercontent.com/vercel/ai/main/packages/provider/src/language-model/v4/language-model-v4.ts)): `specificationVersion: 'v4'`, `provider: string`, `modelId: string`, `supportedUrls: Record<mediaType, RegExp[]> | PromiseLike<…>`, `doGenerate(opts) → {content: Content[], finishReason, usage, providerMetadata?, request?{body}, response?{id,timestamp,modelId,headers,body}, warnings[]}`, `doStream(opts) → {stream: ReadableStream<StreamPart>, request?, response?{headers}}`. V3 is identical in shape.

**A3. Prompt** ([v4-prompt](https://raw.githubusercontent.com/vercel/ai/main/packages/provider/src/language-model/v4/language-model-v4-prompt.ts)). Roles: `system{content:string}`, `user[text|file]`, `assistant[text|file|custom|reasoning|reasoning-file|tool-call|tool-result]`, `tool[tool-result|tool-approval-response]`. Every message and every part carries `providerOptions?: Record<providerKey, JSONObject>`. `tool-call` part: `{toolCallId, toolName, input: unknown, providerExecuted?}`. `tool-result.output` union: `text{value}` | `json{value}` | `execution-denied{reason?}` | `error-text` | `error-json` | `content{value:[text | file{data,mediaType,filename?} | custom]}`. V4 file `data` is a tagged union `SharedV4FileData = data{Uint8Array|base64} | url{URL} | reference{providerReference} | text{text}` (V3: `Uint8Array|string|URL` untagged). V4 adds `custom{kind:"vendor.name"}` and `reasoning-file` parts.

**A4. Stream parts** ([v4](https://raw.githubusercontent.com/vercel/ai/main/packages/provider/src/language-model/v4/language-model-v4-stream-part.ts); V3 identical minus `custom`/`reasoning-file`):

| part | fields |
|---|---|
| `stream-start` | `warnings: SharedWarning[]` (`unsupported{feature}` / `compatibility{feature}` / `deprecated{setting,message}` (V4) / `other{message}`) |
| `response-metadata` | `id?, timestamp?, modelId?` |
| `text-start` / `text-delta` / `text-end` | `id`, `delta` (delta only), `providerMetadata?` on each |
| `reasoning-start/delta/end` | same shape as text |
| `tool-input-start` | `id, toolName, providerExecuted?, dynamic?, title?` |
| `tool-input-delta` / `tool-input-end` | `id, delta` / `id` |
| `tool-call` | `toolCallId, toolName, input: string` (raw JSON), `providerExecuted?, dynamic?` |
| `tool-result` (provider-executed) | `toolCallId, toolName, result: JSONValue, isError?, preliminary?, dynamic?` |
| `tool-approval-request` | `approvalId, toolCallId` |
| `file` / `reasoning-file` | `mediaType, data` |
| `source` | `sourceType:'url'{id,url,title?}` or `'document'{id,mediaType,title,filename?}` |
| `custom` (V4) | `kind: "vendor.name"` + providerMetadata |
| `finish` | `usage, finishReason, providerMetadata?` |
| `raw` | `rawValue` (only if `includeRawChunks`) |
| `error` | `error: unknown` (multiple allowed) |

The `id`-correlated start/delta/end triples exist because providers emit **interleaved parallel blocks** (Anthropic content-block index, OpenAI Responses item ids, parallel tool inputs); metadata that only becomes known at block end (Anthropic thinking `signature`, Google `thoughtSignature`, OpenAI `itemId`) rides on the `-end`/`-start` part's `providerMetadata`.

**A5.** `finishReason` (V3+) is `{unified: 'stop'|'length'|'content-filter'|'tool-calls'|'error'|'other', raw: string|undefined}` ([src](https://raw.githubusercontent.com/vercel/ai/main/packages/provider/src/language-model/v3/language-model-v3-finish-reason.ts)). **Usage is nested already in V3** ([src](https://raw.githubusercontent.com/vercel/ai/main/packages/provider/src/language-model/v3/language-model-v3-usage.ts)): `inputTokens{total,noCache,cacheRead,cacheWrite}`, `outputTokens{total,text,reasoning}`, `raw?: JSONObject`; V2 was flat (`inputTokens, outputTokens, totalTokens, reasoningTokens?, cachedInputTokens?`). `CallOptions` ([v4](https://raw.githubusercontent.com/vercel/ai/main/packages/provider/src/language-model/v4/language-model-v4-call-options.ts)): `prompt, maxOutputTokens, temperature, stopSequences, topP, topK, presencePenalty, frequencyPenalty, responseFormat{text | json{schema?,name?,description?}}, seed, tools, toolChoice{auto|none|required|tool{toolName}}, includeRawChunks, abortSignal, headers, providerOptions` and **V4-new `reasoning?: 'provider-default'|'none'|'minimal'|'low'|'medium'|'high'|'xhigh'`**. Tools: `function{name, description?, inputSchema: JSONSchema7, inputExamples?, strict?, providerOptions?}` | `provider{id:"vendor.name", name, args}`.

**A6. `ai` core.** `streamText` ([stream-text.ts](https://github.com/vercel/ai/blob/main/packages/ai/src/generate-text/stream-text.ts)) options: `stopWhen` (conditions in [stop-condition.ts](https://raw.githubusercontent.com/vercel/ai/main/packages/ai/src/generate-text/stop-condition.ts): `isStepCount`, `isLoopFinished`, `hasToolCall` — `stepCountIs` is the older docs name), `prepareStep`, `activeTools`, `experimental_repairToolCall`, `output`, `toolApproval`, `includeRawChunks`, `experimental_transform`, `onStepFinish/onFinish/onError`. `TextStreamPart` types ([stream-text-result.ts](https://raw.githubusercontent.com/vercel/ai/main/packages/ai/src/generate-text/stream-text-result.ts)): `start, start-step, text-*, reasoning-*, reasoning-file, tool-input-*, tool-call, tool-result, tool-error, tool-output-denied, file, custom, raw, error, abort, finish-step, finish` (+`source` via spec type). `UIMessageChunk` ([ui-message-chunks.ts](https://raw.githubusercontent.com/vercel/ai/main/packages/ai/src/ui-message-stream/ui-message-chunks.ts)) adds the lifecycle envelope: `start{messageId}, start-step, finish-step, reset-step, finish, abort, message-metadata, error`, tool states `tool-input-start/delta/available/error`, `tool-approval-request{approvalId,reason?,isAutomatic?,signature?}`/`-response`, `tool-output-available{preliminary?}/-error/-denied`, `source-url`, `source-document`, `file`, `data-*{id?,data,transient?}`. `UIMessage.parts` ([ui-messages.ts](https://raw.githubusercontent.com/vercel/ai/main/packages/ai/src/ui/ui-messages.ts)): `text{state:'streaming'|'done'}`, `reasoning`, `custom`, `tool-<name>`/`dynamic-tool` with **state machine `input-streaming → input-available → approval-requested → approval-responded → output-available | output-error | output-denied`** (+`callProviderMetadata`, `resultProviderMetadata`, `preliminary`, `approval{id,approved,reason,signature}`), `source-url`, `source-document`, `file`, `reasoning-file`, `data-<name>`, `step-start`. This is the GUI-ready shape; note the SDK derives it deterministically from spec parts + step boundaries.

**A7. Adapters.** [Anthropic](https://ai-sdk.dev/providers/ai-sdk-providers/anthropic): `providerOptions.anthropic.cacheControl{type:'ephemeral', ttl?:'1h'}` on any part; `thinking{type:'adaptive'|'enabled', budgetTokens}`, `effort`, `sendReasoning`, `disableParallelToolUse`, `container`, `toolStreaming`; returns `providerMetadata.anthropic.{cacheReadInputTokens, cacheWriteInputTokens, usage, stopDetails, iterations, contextManagement}`; provider tools `anthropic.tools.bash_20250124 / textEditor_20250728 / computer_20251124 / webSearch / webFetch / codeExecution_20260120 / memory / advisor`. [OpenAI](https://ai-sdk.dev/providers/ai-sdk-providers/openai): Responses API is the default since SDK 5; reasoning parts carry `providerMetadata.openai.{itemId, reasoningEncryptedContent}` (63 `itemId` references in [the model source](https://raw.githubusercontent.com/vercel/ai/main/packages/openai/src/responses/openai-responses-language-model.ts)), auto round-tripped; options `reasoningEffort, reasoningSummary, store, previousResponseId, include:['reasoning.encrypted_content'], serviceTier, promptCacheKey`. [Google](https://ai-sdk.dev/providers/ai-sdk-providers/google): `providerMetadata.google.thoughtSignature` on reasoning/tool-call parts, auto round-tripped; `thinkingConfig{thinkingLevel|thinkingBudget, includeThoughts}`. Bedrock: `providerOptions.bedrock.reasoningConfig{budgetTokens|maxReasoningEffort}`, metadata `trace, performanceConfig, serviceTier, usage` ([deepwiki](https://deepwiki.com/search/how-do-the-aisdkanthropic-aisd_426801c2-c1ed-45e8-b67e-efaa1f82378f)). `convertToLanguageModelPrompt` lives at `packages/ai/src/prompt/convert-to-language-model-prompt.ts` (UIMessage/ModelMessage → spec prompt, incl. URL download). [`provider-utils`](https://github.com/vercel/ai/tree/main/packages/provider-utils/src) exports `postJsonToApi`, `createJsonResponseHandler`, `createEventSourceResponseHandler`, `parseJsonEventStream`, `generateId`, `parseProviderOptions`, `mapReasoningToProvider{Effort,Budget}`, `retryWithExponentialBackoff`, `streaming-tool-call-tracker`, `resolveProviderReference`; built on `eventsource-parser@3` + `undici`. `@ai-sdk/gateway@4.0.67` is a hosted router (`order`, `only`, `sort`, `models` fallback, `byok`, unified `serviceTier`).

## B. litellm

**B1.** v1.98.0 (PyPI 2026-08-22), ~57.5k stars, 45k commits; **MIT except `enterprise/` (commercial license)** ([LICENSE](https://raw.githubusercontent.com/BerriAI/litellm/main/LICENSE)). Surface is OpenAI chat-completions: `ModelResponse{choices[{index, finish_reason, message}], usage}`; `Message{content, role, tool_calls, function_call, audio, images, reasoning_content, thinking_blocks, reasoning_items, provider_specific_fields, annotations}`; streaming `ModelResponseStream{choices[StreamingChoices{delta: Delta}]}` with `Delta{content, role, tool_calls[ChatCompletionDeltaToolCall{id?, index, type, function{name,arguments}}], reasoning_content, thinking_blocks, reasoning_items, provider_specific_fields}` ([types/utils.py](https://raw.githubusercontent.com/BerriAI/litellm/main/litellm/types/utils.py)). `thinking_blocks`: `{type:'thinking', thinking, signature, cache_control?}` | `{type:'redacted_thinking', data}` ([openai.py](https://raw.githubusercontent.com/BerriAI/litellm/main/litellm/types/llms/openai.py)). `Usage{prompt_tokens, completion_tokens, total_tokens, prompt_tokens_details{cached_tokens, cache_creation_tokens, text/image/video…}, completion_tokens_details{reasoning_tokens,…}, cache_creation_input_tokens, cache_read_input_tokens, server_tool_use, cost}`. `finish_reason` collapsed to `stop|length|tool_calls|function_call|content_filter`, original in `provider_specific_fields.native_finish_reason` ([output docs](https://docs.litellm.ai/docs/completion/output)). `CustomStreamWrapper` (`litellm_core_utils/streaming_handler.py`) re-chunks every provider into OpenAI deltas; `stream_options.include_usage` appends a usage chunk; `stream_chunk_builder` reassembles ([stream docs](https://docs.litellm.ai/docs/completion/stream)). Routing: `completion(model="provider/model")` → `get_llm_provider` (`get_llm_provider_logic.py`) by prefix / api_base heuristics. Per-provider `BaseConfig` ([transformation.py](https://raw.githubusercontent.com/BerriAI/litellm/main/litellm/llms/base_llm/chat/transformation.py)): `get_supported_openai_params, map_openai_params, validate_environment, sign_request, get_complete_url, transform_request, transform_response, get_model_response_iterator, get_sync_custom_stream_wrapper, should_fake_stream, is_thinking_enabled, calculate_additional_costs, get_error_class`. `Router` (SDK-usable without proxy): strategies simple-shuffle / least-busy / latency / usage-v2 (Redis) / cost / custom; `fallbacks`, `context_window_fallbacks`, `content_policy_fallbacks`, cooldowns (`allowed_fails`), retries ([routing](https://docs.litellm.ai/docs/routing)). Prompt caching = `cache_control` on content blocks, translated per provider ([docs](https://docs.litellm.ai/docs/completion/prompt_caching)). Reasoning: `reasoning_effort` → Anthropic adaptive thinking/`budget_tokens`, and **since OpenAI chat spec has no `thinking_blocks` field, callers must manually echo `thinking_blocks` back for Anthropic multi-turn tool use** ([reasoning docs](https://docs.litellm.ai/docs/reasoning_content)).

**Price JSON** ([raw](https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json)): 3,365 entries, 1.97 MB, 160 distinct keys, modes `chat 2558 / embedding 134 / image_generation 271 / responses 92 / …`; ~5–7 commits/day. Fields (from `claude-sonnet-4-5` / `gpt-5` entries): `max_tokens, max_input_tokens, max_output_tokens, input/output_cost_per_token` (+`_above_200k_tokens`, `_flex`, `_priority` tiers), `cache_read_input_token_cost`, `cache_creation_input_token_cost(_above_1hr)`, `litellm_provider, mode, deprecation_date, prompt_cache_min_tokens, supported_endpoints, supported_modalities, supports_{function_calling, parallel_function_calling, vision, pdf_input, reasoning, prompt_caching, response_schema, native_structured_output, tool_choice, computer_use, assistant_prefill, web_search, xhigh_reasoning_effort…}, search_context_cost_per_query`. There is a `model_prices_and_context_window.schema.json`.

**B2. Weaknesses as a reference:** (i) OpenAI-delta lowest common denominator — no block ids; parallel reasoning/text/tool blocks collapse into `index`-correlated deltas; (ii) `provider_specific_fields` / `thinking_blocks` / `reasoning_items` are bolt-ons the OpenAI shape can't express, pushing round-trip responsibility onto callers; (iii) finish reasons lossy; (iv) Python-only, 4,200-line `types/utils.py`, 100+ transformation classes — not portable, only mineable.

## C. Comparison for a Rust kernel

The Vercel V4 spec is the closer reference: typed content blocks, `id`-correlated `start/delta/end`, `providerExecuted`/`dynamic`/approval flow, nested cache/reasoning usage, `{unified, raw}` finish reason, and a two-level escape hatch (`providerOptions` in, `providerMetadata` out, keyed by provider) — exactly what a coding agent's tool loop and GUI need, and the `UIMessage` state machine is a free derivation from it. litellm is the better reference for *provider coverage tables and pricing data*, not for the event model.

**Recommended Rust shape** (mirror V4, own it):
```rust
enum StreamPart { StreamStart{warnings}, ResponseMetadata{id,model_id,timestamp},
  TextStart{id,meta}, TextDelta{id,delta}, TextEnd{id,meta},
  ReasoningStart/Delta/End{..}, ToolInputStart{id,tool_name,provider_executed,dynamic},
  ToolInputDelta{id,delta}, ToolInputEnd{id},
  ToolCall{tool_call_id,tool_name,input:String /*raw JSON*/,provider_executed,dynamic,meta},
  ToolResult{tool_call_id,tool_name,result:Value,is_error,preliminary}, ToolApprovalRequest{approval_id,tool_call_id},
  File{media_type,data}, Source(Source), Custom{kind,meta}, Raw(Value),
  Finish{usage:Usage, finish_reason:{unified:FinishReason, raw:Option<String>}}, Error(Error) }
type ProviderMetadata = BTreeMap<String, serde_json::Map<String,Value>>; // keyed by provider
struct Usage { input:{total,no_cache,cache_read,cache_write}, output:{total,text,reasoning}, raw:Option<Value> }
```
Keep `Message`/parts with `provider_options` on every message and part; keep `input` as raw JSON string in the stream (parse once at the loop boundary, as the SDK does).

**Catalog data:** prefer [models.dev](https://models.dev/api.json) — MIT, TOML per provider/model ([repo](https://github.com/sst/models.dev)), 204 providers / 7,439 models / 4.4 MB, ~30 commits/day incl. automated catalog syncs; per-model `id, name, family, attachment, reasoning, reasoning_options[{type:'effort',values}|{type:'budget_tokens',min}], tool_call, structured_output, temperature, knowledge, release_date, last_updated, modalities{input,output}, open_weights, limit{context,input,output}, cost{input,output,cache_read,cache_write}` (USD/1M), `status, experimental, interleaved`; provider `id, name, env[], npm, api, doc`. Its `id` is the AI-SDK model id and `npm` names the `@ai-sdk/*` package, so it's aligned with the Vercel model. Also `models.json` (provider-agnostic) and `catalog.json`. litellm's JSON is MIT too and richer in pricing tiers/endpoint flags, but keyed by litellm's routing strings. Caveat: they disagree on facts (models.dev says Sonnet 4.5 `context: 1_000_000`; litellm says `max_input_tokens: 200000`) — validate against vendor docs.

**Verdict:** no crate is adoptable as *the* provider layer. `rig-core` is the only one whose stream model has correlation ids, reasoning signatures, encrypted reasoning, and Responses API — but it drags in an agent/vector-store framework and its own opinions. `aisdk`/`genai` flatten blocks (no ids). **The kernel should own its adapters** (Anthropic Messages, OpenAI Responses, Gemini, OpenAI-compatible chat, Bedrock via `aws-sdk-bedrockruntime`), with the V4-mirrored `StreamPart` above as the contract, built on `reqwest` + `eventsource-stream` (or `sse-stream`), borrowing wire types from `async-openai` where convenient and reading `rig-core/src/completion/message.rs` and `zerx-lab/llmsdk` as prior art. Use models.dev for the catalog; cross-check litellm's JSON for pricing tiers.

Unverified: litellm contributor count and litellm price-JSON commit cadence beyond the 8 visible commits; `llmsdk`'s and `llm_adapter`'s actual feature depth (README claims only); `graniet/llm` thinking-signature round-trip.
